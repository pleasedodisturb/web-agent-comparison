## Falsifiability of research/SUMMARY.md claim

> Claim: "obscura — CDP-direct (not Playwright-on-CDP) gives lower overhead +
>         ~30MB RAM vs Playwright ~300MB while keeping full JS rendering"

**Verdict on the memory claim:** PARTIALLY SUPPORTED.
- Mean RSS 32.4 MB is within ~10% of the claimed "30 MB" — claim holds for
  steady-state, not for peak.
- Peak RSS 57.8 MB is roughly 2× the claimed number — under load (S1 nav +
  eval), the wrapper's Node process consumes notably more than the published
  ~30 MB. Still ~5× smaller than the claimed Playwright "~300 MB" baseline.

**Caveats this measurement cannot resolve:**
1. We sampled the WRAPPER process (PID 57077, `node /opt/homebrew/lib/...obscura serve`),
   not the underlying Chromium worker. The CDP server (port 9222) is presumably backed
   by a Chromium instance with its own RSS that does not show under `obscura` in `ps`.
   Total architecture footprint is HIGHER than 57.8 MB.
2. No Playwright control measurement in this run — the 300 MB Playwright comparison
   number comes from research/SUMMARY.md, not from a side-by-side measurement on this
   host. A clean A/B (Phase 3 / G-710 territory) is required to falsify the
   "~10× lighter" claim definitively.

**Verdict on the "full JS rendering" claim:** SUPPORTED.
- S1 explicitly triggered the Greenhouse React bundle (it clobbered the SSR
  content with a "Page not found" 404 component — see DEEP_ANALYSIS.md §2).
- The bundle ran. obscura is NOT JS-light like lightpanda; it executes a real
  Chromium runtime under the CDP server. The Ashby SPA stage (S2) failed for
  a different reason (CDP target wedge after sync XHR — see DEEP_ANALYSIS.md §3),
  NOT because JS didn't run.
