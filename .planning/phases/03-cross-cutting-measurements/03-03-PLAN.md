# Why we extend tools_inventory.py rather than rewrite:
# tools_inventory.py already does the work — load_mcp_spec, stdio_client,
# ClientSession.initialize, session.list_tools. We add timing instrumentation
# around those calls. NO need to re-implement the JSON-RPC client.

# 3-segment definitions (from 03-CONTEXT.md Decisions):
#   t_resolve       = process spawn → first byte of stdout
#   t_spawn         = first byte of stdout → MCP server ready to accept initialize
#                     (== time from "process alive" to "session.initialize() returns")
#   t_first_useful  = initialize sent → first tools/list response received
#                     (== time from initialize-complete to list_tools-complete)
#
# Implementation note: with mcp.client.stdio's high-level API we don't have a
# direct hook for "first byte of stdout" — the SDK wraps the read pipe. Use
# this pragmatic decomposition:
#   t_resolve    = wall time from before stdio_client.__aenter__() to entered
#                  (process spawn + first protocol exchange to set up the read/write streams)
#   t_spawn      = wall time from streams ready to session.initialize() returning
#   t_first_useful = wall time from initialize-returned to list_tools-returned
# Document this approximation in cold_start.json metadata. This is faithful
# enough for the cross-MCP comparison and avoids re-implementing the JSON-RPC
# read loop.

# Cold-vs-warm methodology (from 03-CONTEXT.md):
#   COLD: pkill -f <binary-name pattern> first; then run; first-spawn-of-session
#   WARM: immediately following the cold run (binary still in OS page cache);
#         run with NO pkill.
# Per CONTEXT.md decisions: "Skip sudo purge if not available; document the
# limitation. The 'cold' timing approximates 'first-spawn-of-shell-session'
# rather than 'uncached-filesystem.'" Record cache_eviction="process_only" in
# metadata.

# Sample count: ≥5 per cold and ≥5 per warm. Per MCP: 10 runs × ~3s each
# (worst case) = ~30s per MCP × 7 MCPs ≈ 3.5 min for the measurement loop.
# Add browser-use-agent (probe is the same binary as direct) — total still
# under 25 min wall clock.

# Special-case MCPs:
# - cloakbrowser: closed-source binary. Per cloakbrowser_guard, we don't need
#   to hit any URL — cold-start is purely process-spawn timing. Safe.
# - firecrawl: cloud-only. Cold-start IS the local Node process spawn timing
#   (firecrawl-mcp's npm wrapper); it does NOT include the cloud Firecrawl
#   roundtrip. Document this in metadata.notes.
# - lightpanda: has the known binary-vs-handshake version mismatch. Cold-start
#   timing is unaffected (we measure spawn, not version semantics).
# - browser-use-direct vs browser-use-agent: identical MCP key in .mcp.json
#   ("browser-use"), differ only at agent-session time. Measure once, copy
#   cold_start.json to both directories with mode-specific metadata.
</context>

         a. Run `pkill -f <pattern>` for each pattern in the MCP's list. Sleep 200ms after pkill (let OS clean up the process group). Skip if `--skip-pkill`.
         b. Start timer `t0 = time.perf_counter_ns()`.
         c. `async with stdio_client(server_params) as (read, write):` — record `t1` upon entry.
         d. `async with ClientSession(read, write) as session:` — record `t1b` upon entry (small).
         e. `await session.initialize()` — record `t2` after returning.
         f. `await session.list_tools()` — record `t3` after returning.
         g. Compute t_resolve = (t1 - t0)/1e6 ms; t_spawn = (t2 - t1)/1e6 ms; t_first_useful = (t3 - t2)/1e6 ms; total = (t3 - t0)/1e6 ms.
         h. Append to `cold_samples`.
         i. Catch asyncio.TimeoutError or Exception → append error record `{run: N, error: ...}` and continue.
      4. For each warm run (default 5) — same loop but skip pkill.
      5. Compute median per-segment over successful samples (use statistics.median; min/max too).
      6. Write cold_start.json to --out.
      7. Exit codes: 0 = all runs OK or some runs OK with failures recorded; 2 = all runs failed.
